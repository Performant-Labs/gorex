**Verdict:** BLOCK

## Summary

BLOCK, with two block findings. The plan adds GoRex's first second native window, but the command dispatch it connects to only knows about the main window. Menu `Click` handlers ignore the `*mygo.Window` they receive, and `App.run` acts only on `a.win`. On macOS, menu key equivalents work across the whole app, so ⌘W pressed in Settings runs Shell ▸ Close Pane on the main window and ends that pane's session. The brief only covers Windows' Esc/Ctrl+W. The second block: the brief has no Reuse map or extend-vs-new line, so the Phase 8 anti-duplication gate has no named object to check against. This plan has three real duplication risks: the preference mutation path, the window lifecycle, and how the command and shortcut are registered. Apart from these, the plan puts things where the codebase expects them: v2 and the migration in `settings.go`; the command table, `menu()` and `shortcuts()` in `commands.go`; the shortcut exception in README.

## Notes for O

Amend `brief.md`, then start a fresh run (not `resumeFromRunId`):

1. **Add a section "Commands while Settings is the key window" (resolves finding 1).**
   - Menu items built by `item()` in `App.menu()` check the window their `Click` receives.
   - When that window is the Settings window, Close Pane's item (⌘W on macOS, Ctrl+Shift+W elsewhere) closes Settings, and no pane or tab command acts on the main window.
   - `App.run`'s "no main window" exception, which exists today for New Tab, also covers Settings, so GoRex ▸ Settings… works after the main window is closed.
   - Add the acceptance item: "⌘W (Ctrl+W on Windows and Linux) with Settings frontmost closes Settings and closes no pane."
2. **Add a section "Reuse & extend-vs-new" (resolves finding 2):**
   - EXTEND `App.setAppearance` / `App.setFontSize` (`settings.go`) as the only writers of appearance and Default's text size. The Settings controls, the menu, the palette and ⌘+ / ⌘− / ⌘0 all call them. They also sync the View ▸ Appearance radio items (`MenuItem.SetChecked` on items App keeps from `menu()`) and invalidate the open Settings window.
   - EXTEND the `command` table in `commands.go` with `cmdSettings`: Title "Settings…", Accel "CmdOrCtrl+,", Keys "⌘,", `Other: shortcut{ui.Ctrl, ui.KeyComma}`. Add it to `paletteCommands`. Its menu item comes from `item(&cmdSettings)`, and Windows' main-window Ctrl+, comes from the existing loop in `shortcuts()`, not a hand-written case. Add `ui.KeyComma` to `shortcut.String()`.
   - FOLLOW `App.open` (`main.go`) to create the Settings window: `mygo.WindowOptions` with `Content: ui.View(...)`, and `OnClosed` clearing the field. Its state lives on `App`, outside `App.reset()`.
   - REUSE `attach`'s display-only terminal (`terminal.New` + `nopConn{}` + `lightTerm` / `darkTerm`) for the live preview, and the `colors` struct / `colorsOf` for the window's colors.
   - NEW, justified because no settings UI or second window exists to extend: the Settings window, its view (`func (a *App) settingsView(c *ui.Context)`), in one new one-word file listed in README's Layout table.
3. **Recommended in the same edit** (warns, not required for PASS): the test seam in finding 3, the write gate in finding 7, the `"system"` spelling in finding 5, and a `Forward-compat:` line per finding 11.
